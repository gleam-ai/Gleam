# GLEAM APP DESIGN v0.1

> 微光 · Gleam 桌面客户端 —— 用户每天打开来干活的界面
> 与 `GLEAM-DESIGN.md`（官网营销页）**并列而非从属**：官网要"被记住"，App 要"被忘掉"。
> 本文件是 App 界面的机器可执行设计约束。改 `internal/webui/static/` 前必须先读。

---

## 0. 定位：App 不是营销页

| 维度 | 官网（GLEAM-DESIGN.md） | 本 App |
|---|---|---|
| 用户状态 | 路过，3 秒决定去留 | 每天坐 8 小时 |
| 审美目标 | 被记住 | **被忘掉**——界面不抢戏，事被做完才抢戏 |
| 底色 | 暗底 `#0E1014` 单点微光 | **不套用官网暗色方案**；浅色壳 + 用户可切换 light/dark/system + accent |
| 主要风险 | 像模板 | 像仪表盘——信息过载、状态色噪声、每张卡都喊 |

**三条推论**：① 能常驻的不喊（已完成必须安静）；② 状态色必须可信（不被装饰色劫持）；③ 出了事必须一眼看到、一眼点到（失败/待批准的唯一入口在 feed 摘要横幅）。

---

## 1. 响度分级原则（本文件最重要的一节）

**信息分级 ≠ 响度分级。** feed 里绝大多数是已完成——状态层级拉得越高，完成态噪声越大，需要介入的那张反而被淹没。

三档响度（卡片第 1 级按这个分，不按信息类型分）：

| 响度 | 状态 | 处理 |
|---|---|---|
| **响** | 失败 / 需批准 | destructive / warning 色 + 完整 badge；审批卡整体 warn 底（"在等你"不是"失败了"） |
| **中** | 进行中 | `--state-run` 青 + 呼吸点 |
| **静** | 已完成 / 已取消 | 中性 `--color-fg-faint` 对勾，**不给 success 绿、不给 accent、不给 score-ring 底色** |

- 已完成是**默认背景**，不是需要被注意的信息。
- success 绿只出现在两处：① "刚完成"的瞬时反馈（`score-ring--just`，6 秒后退回中性）；② LiveRail 步骤完成态。
- 已取消是用户自己的决定，不是故障：中性，不沾红。

## 2. 四态语义表

| 状态 | token | 浅色 | 深色 | 浅色对比度 | 深色对比度 | 动效 |
|---|---|---|---|---|---|---|
| 运行中 | `--state-run` | `#0e7490` | `#06b6d4` | 4.91:1（算） | 7.42:1（算） | 呼吸 1.8s |
| 待处理 | `--color-warning` | `#a86a10` | `#eab264` | — | — | **空心环** |
| 失败 | `--color-destructive` | `#d93b3b` | `#f05b5b` | — | — | 静止 |
| 完成 | `--color-success` | `#26734a` | `#4cc38a` | 5.29:1（算） | 7.86:1（实测） | 静止 |

- `--state-run` 是**本文件新增**的 token；`--color-success` 从 05-consistency 提升为正式状态色（合同变了，浅色值因此从 `#2f8f5b`（3.70:1）加深到 `#26734a`）。
- **形态维度**：等待 = 空心环，失败 = 实心点。原因：琥珀与红正常视力 ΔE=31.9 可辨，但 L\* 仅差 1.1——红绿色觉障碍（约 8% 男性）眼里两者坍缩为同一黄灰（CDP deuteranopia 模拟已实证：两枚色样渲染为同一橄榄灰）。色相上没空间了，用形状兜底，且正常视力多一层线索。
- `prefers-reduced-motion` 下动效全关（08-ia.css 有通配兜底），只剩色相 + 形状——**反向印证 state-run 定在青色空带中心是对的**：那是唯一在 reduced-motion 下也不与任何 accent 混淆的色相。

## 3. accent 色相空带表（26 个取值全量实测）

`--color-accent` 是**用户自选的装饰色**（5 套 × 深浅 + 各层覆盖）。状态色不得与它撞色。全量 hue 实测（grep 全部 `--color-accent` 字面量后逐个计算）：

| hue 区间 | 占用 |
|---|---|
| 15–17 | parchment（4 值） |
| 26 / 37 | amber |
| 41.7 / 47 / 48.2 | bee |
| 73.3 | 06-features 扩展 |
| 135.2–167.9 | emerald / mint 全部（10 值，最近的浅色 mint `#13806a` = 167.9） |
| **170–200** | **空带（无任何 accent）** |
| 218.2 / 221.2 | blue |
| 247.4 / 249.1 | violet |
| 328.6 / 333.3 | rose |

`--state-run` 取 hue 192.9（青），位于全表最宽空带的中心，两侧各距 25°。

**运行时保险**：`guardStateRunHue()`（app.js）读当前 accent 的计算 hue，与 195 相差 <15° 才把 `--state-run` 回退为中性灰蓝（浅 `#475569` / 深 `#94a3b8`）。现存 26 个取值永不触发；它是给将来新增青色 accent 的保险，已实跑验证（撞色→回退、还原→清除、不自锁）。

**判定方法（防止再次翻车）**：任何"状态色不与装饰色撞"的结论，必须贴全量 hue 实测表；HSL 色相角不线性对应感知距离，色相邻近 ≠ 可分辨（ΔE 才是感知距离），两者都要算。

## 4. 动效统一语法

**脉冲 = 活跃/运行中。跨区域一个来源、一个时长、一种颜色。**

- 唯一定义：`@keyframes status-breathe`（08-ia.css），box-shadow 扩散环（5px 点上唯一可见的形态），1.8s。
- 使用者（五处）：`.rail-pulse[running]`、`.rail-strip-dot[running]`、`.loop-step[active] .loop-node`、`.badge--running::before`、`.timeline-item--active::before`。
- 已完成/等待/失败全部静止。
- 废弃：`dot-pulse`（1.8s accent 环）与 `rail-breathe`（1.9s opacity+scale+环）——两套动效语言讲同一件事，已无规则引用；旧 keyframes 保留在 01-base 不删。
- `prefers-reduced-motion` 下全部静止（通配兜底写在 08-ia.css）。

## 5. 状态色不得被装饰色劫持——判定与纠正记录

**判定**：某颜色若同时满足①表达状态语义（运行/等待/失败/完成）②取自用户可自选的装饰 token（`--color-accent`），即为劫持。用户换皮肤时状态语义会跟着变（选 bee 皮肤时"运行中"变土黄）。

**本轮纠正记录**：

| 位置 | 误用 | 纠正 |
|---|---|---|
| `.badge--running` / `.badge--success` | accent 底 + accent 字 | state-run 青 / 中性 faint |
| `.timeline-item--active::before` | accent 边框 + accent 脉冲 | state-run + status-breathe |
| `.rail-pulse[running]` / `loop-step[active]` / `flow-dot[active]` | accent | state-run |
| `.readout-row dd[data-tone="ok"]` | accent | `--color-success` |
| `score-ring` 默认描边 | accent | `--color-fg-faint` |

## 6. 失败态规范

失败是**记录**，不是首页横幅：首页只给问候与输入框，任务状态由左侧「任务记录」的标签承担，失败详情收在会话 / 任务详情里。

1. **分级**：一行白话摘要（如「模型鉴权失败：API Key 无效、过期或未填写」）+ 可展开的「技术详情」。
2. **原文一律不删**：`result.error` 全文进 `<pre>`（如 `llm: HTTP 401: Authentication Fails (governor)`）。摘要可以翻译，原文必须原样可查。
3. **状态标签**：侧栏每个会话按最新任务显示「处理中 / 待批准 / 失败 / 部分完成 / 已停止 / 成功」；待审批优先于任务状态，任务定格后不再悬挂。
4. **恢复入口在详情**：失败/部分完成任务的详情给「重新填写」——目标填回输入框，不自动提交；鉴权类错误（匹配 `/401|403|Authentication|unauthorized|invalid.{0,20}key/i`）另给「去配置 API Key」，落到出错那家厂商的密钥框。
5. **红色纪律**：仅失败态（callout 图标/标题、失败标签、failed 徽章）。审批卡是 warn 不是红。
6. **provider 不从错误文本解析**：错误串里没有可靠厂商标识（`(governor)` 不是 provider id）。唯一可靠来源是任务自带的 `result.config_snapshot.provider`；解析不出就落 llm 页签顶部，不猜。

## 7. 分数信号（Reflect 的可见性）

自评分 0–100 是 Gleam 的核心差异化（低分自动重规划）。完成态虽静，**分数不许被安静吞掉**：52/100 和 96/100 在 feed 里不能长得一样。

- 阈值 `SCORE_LOW = 70`（app.js 常量）：低于它 → 数字回 `--color-fg`、环描 `--color-warning`；其余全静。70 是产品判断（"明显低于默认期望"一档），非统计值。
- 背景/对勾/标题不动——响度仍是静，只有分数本身保留信号。

## 8. 反模式清单

- [ ] 装饰色（`--color-accent`）当状态色用（见 §5 记录表）
- [ ] 完成态给 success 绿 / accent / 实色 ring（完成必须安静）
- [ ] 已取消沾红（取消是用户的决定，不是故障）
- [ ] 两处 UI 对同一事实给出不同答案（侧栏标签 vs 会话状态、徽章 vs 读数、竖签 vs 面板）
- [ ] 卡片农场：等宽 grid、每卡一图标（App 内同样禁止）
- [ ] 动效语言不统一（同一语义两套 keyframes / 两个时长）
- [ ] `prefers-reduced-motion` 下仍有动画（新增动画必须补兜底）
- [ ] 无数据的界面元素（解析不出就落默认，不猜、不编）
- [ ] 「重新填写」偷偷覆盖输入框并直接提交（填回后由用户确认发送）
- [ ] 从错误文本解析结构化信息（provider 等）
- [ ] 等宽四宫格统计（数字用 inline 事实条，官网 §9 签名三同样适用）

## 9. 壳层与导航（第 10 层）

- **常驻导航只有会话**：侧栏不再列模块；模块与动作统一走 `Ctrl+K` 命令面板（动作 / 跳转两组，会话与目标排在其后）。菜单栏、aux 启动器与底部工具箱入口已退休。
- **一个主区**：顶栏只覆盖主区，侧栏独占整列高度；主区是平面画布，不再有舞台卡与常驻现场仪表盘。
- **现场栏按需**：`#rail-open` 打开右侧抽屉，宽度 `min(360px, 92vw)`，从顶栏下沿起，不挤压主区；命令面板（z 140）在它之上。
- **终端贴底**：终端占主区下方独立 grid 行；打开时主区缩短，不覆盖内容。
- **首页只做起始页**：问候 + 三条起步建议 + 输入框，作为一列整体垂直居中；任务卡与失败横幅都不上首页，记录改由左侧「任务记录」承担——每个会话带「处理中 / 待批准 / 失败 / 部分完成 / 已停止 / 成功」标签。进入对话后输入框回到底部，消息流吃满剩余高度。
- **窄屏（≤900）**：侧栏变为 300px 浮层，`#sidebar-toggle` 控制；点击浮层内任意按钮或会话后自动收起；主区吃满整宽。

### 反模式补充

- [ ] 同时常驻多套导航（侧栏模块 + 顶栏菜单 + 常驻仪表盘）
- [ ] 首页内容贴顶或贴底、留出一大块无重心的空白
- [ ] 首页在输入框上方堆任务卡或失败横幅（状态属于侧栏记录）
